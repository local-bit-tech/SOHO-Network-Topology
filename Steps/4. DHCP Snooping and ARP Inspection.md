# DHCP Snooping and ARP Inspection Configurations

Enabling DHCP snooping  is important for L2 devices to protect your LAN from attackers who might spoof IP addresses or MAC addresses. 
DHCP snooping prevents your DHCP pool from running out (DHCP exhaustion) by binding your IP address that you leased from the server to your MAC address.
The trigger for DHCP snooping occurs with the same IP address coming from a different MAC address or if a fraudulent DHCP server is trying to lease IP addresses on an untrusted port.

ARP inspection would check the DHCP snooping binding table and ARP ACLs to make sure the node claiming to be a specific IP address is actually who they say there.
ARP inspection basically doesn't trust anything that end-nodes might say about who they are until it can be verified by the DHCP snooping table and ARP ACLs.



## DHCP Snooping

<img width="1963" height="760" alt="image" src="https://github.com/user-attachments/assets/f5c2959c-63d4-4985-98ed-0f0ed17c4860" />

From the image above, we can analyze DHCP snooping in more understandable terms. We would configure a port as trusted and that specific trusted port can send DHCP Offer and ACK messages.
Whereas the untrusted ports (which are by default untrusted) would not be able to send DHCP server messages.


Configuring DHCP Snooping on SW2:
```text
SW2(config)#ip dhcp snooping
SW2(config)#ip dhcp snooping vlan 10,20
SW2(config)#int range f0/1-2
SW2(config-if-range)#ip dhcp snooping trust
SW2(config)#no ip dhcp snooping information option
```

Configuring DHCP Snooping on SW1:
```text
SW1(config)#ip dhcp snooping
SW1(config)#ip dhcp snooping vlan 10,20
SW1(config)#no ip dhcp snooping information option
SW1(config)#int g0/1
SW1(config-if)#ip dhcp snooping trust
```

We first enable DHCP snooping then enable it for the specific VLANs we will use in this topology. 
Then an important step is to make sure all uplink ports are configured as trusted so they don't have to go through the DHCP snooping process.
The last step is to disable option 82 for DHCP snooping which if we didn't disable would cause R2, once the DHCP Discover message is received, to drop the packet.

Checking the DHCP Snooping Binding table, we see that the port, IP address, and MAC address are all populated when we try to renew our DHCP lease.

## ARP Inspection

ARP Inspection compares to what it knows from the ARP ACLs and DHCP Snooping binding table and then compares it to the sender IP and MAC address.
If everything matches, then it passes through. If not, then the port gets errdisabled.

<img width="1672" height="840" alt="image" src="https://github.com/user-attachments/assets/507c62bf-9cbe-4345-90c4-28dc406bb189" />

Seeing from the image, if we have the DHCP snooping binding table populated, then it should detect the rogue server's MAC address does not match what it has in the binding table and discard that frame.

ARP Inspection Configuration on SW2:
```text
SW2(config)#ip arp inspection vlan 10,20
SW2(config)#int range f0/1-2
SW2(config-if-range)#ip arp inspection trust
```

We only enable ARP inspection for the vlans we will use. Then, like DHCP snooping, we will trust the uplink connections.

ARP Inspection Configuration on SW1:
```text
SW1(config)#ip arp inspection vlan 10,20
SW1(config)#int g0/1
SW1(config-if)#ip arp inspection trust
```
SW1's configurations are almost the same as SW2 except we change the uplink connections from FastEthernet0/1 and FastEthernet0/2 to GigabitEthernet0/1.
