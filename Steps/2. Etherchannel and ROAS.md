# Etherchannel and ROAS

In this section, we will configure etherchannel (LACP) between SW1 and SW2.
We will also be enabling ROAS (Router On A Stick) on R1.


## Etherchannel configuration

Etherchannel solves a problem with STP and having multiple ports connected on the same switch to increase bandwidth.
Normally, STP would only allow for one connection to receive and forward frames and thereby not allowing for multiple connections to one switch to work.

In this diagram, this is how STP would work before we enable etherchannel.
<img width="1905" height="337" alt="image" src="https://github.com/user-attachments/assets/2adfa564-0a7f-4898-8f08-fabaddbcb31f" />

We see on the second switch the lower connection is being blocked and not sending/receiving frames.

<img width="1878" height="347" alt="image" src="https://github.com/user-attachments/assets/5c2e1ee3-6a69-4cdc-add2-6e37b2f60076" />

However, on this new diagram with etherchannel being enabled, we see that a new link aggregation group (LAG) is formed indicated by the circle on the cables.


To begin with the configurations, we apply these commands:
```text
SW1(config)#int range f0/1-2
SW1(config-if-range)#channel-protocol lacp
SW1(config-if-range)#channel-group 1 mode active
SW1(config-if-range)#int port-channel1
SW1(config-if)#switchport mode trunk
SW1(config-if)#switchport trunk allowed vlan 10,20
```

First, we go into the interfaces where we wish to apply the LAG to, in our case interfaces FastEthernet0/1 and FastEthernet0/2.
We apply a standards-based etherchannel protocol, LACP (IEEE 802.3ad), onto these cables.
Second, we apply the group we will aggregate the cables to and use an active linking method.
Third, we go into the port channel and trunk it so that it allows multiple vlans to pass through it.

<img width="426" height="108" alt="image" src="https://github.com/user-attachments/assets/2ad0f9c8-c171-49e1-9917-f5385dafb1d9" />

After applying these commands on both switches, you should see both ports have green lights on SW1.

To verify our LAG has been created, we can run the do show etherchannel command:

<img width="334" height="132" alt="image" src="https://github.com/user-attachments/assets/0bf2eb24-c005-4ffa-8361-b0d3e9181dad" />

This not only shows the fact that the etherchannel is using LACP but it has two ports that are being used.
LACP should allow for 8 total ports to be aggregated; however, there can be a total of 8 extra ports that can be backed up if one of the ports fails.

## ROAS

Router on a stick (ROAS) solves a problem with a switch trying to send traffic from many vlans on one link with a router.

<img width="580" height="861" alt="image" src="https://github.com/user-attachments/assets/2caa788e-f6d2-4229-ad47-409681f7e1ed" />

From this image, we see that there are three different vlans represented by three different connections. Each vlan can use its own connection.
However, if we have tens, maybe even hundreds, of vlans then this would obviously be unfeasible.
ROAS solves this by applying sub-interfaces that act like a singular connection on a singular connection as seen in the image below.

<img width="633" height="910" alt="image" src="https://github.com/user-attachments/assets/20e6548e-0ada-4c62-b539-17559f92bc28" />

The image is trying to show the curved black wire is encapsulating all three sub-interfaces into a singular interface.

To configure ROAS, we will apply these configurations on R2 as it is connected to SW1.

```text
R2(config)#int g0/0/1
R2(config-int)#no shutdown
R2(config-int)#int g0/0/1.1
R2(config-subif)#encapsulation dot1q 10
R2(config-subif)#ip add 192.168.1.254 255.255.255.0
R2(config-subif)#int g0/0/1.2
R2(config-subif)#encapsulation dot1q 20
R2(config-subif)#ip add 192.168.2.254 255.255.255.0
```

First, we go onto interface configuration mode for GigabitEthernet0/0/1 (connected to SW1) and turn on the interface with the no shutdown command.
Then, we go into a sub-interface for vlan 10. Apply the dot1q encapsulation command for vlan 10. Then, apply an ip address within the /24 subnet to this sub-interface.
Do the same for the VLAN 20 except change the commands as seen above.

Now, the router will be able to route ip addresses between different vlans on a singular connection (cable) to SW1.
