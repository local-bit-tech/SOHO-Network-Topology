# OSPF and DHCP Configurations

We will fill the routing table on R1 with routes to the 192.168.1.0/24 and 192.168.2.0/24 subnets via OSPF. Then we will configure R1 as a DHCP server that will lease out ip addresses to the two subnets using R2 as a DHCP relay agent.

## OSPF

Open Shortest Path First (OSPF) is a dynamic routing protocol. Basically, it allows for routers to learn routes instead of having to manually configure each subnet on the routing table.
OSPF uses Dijkstra's algorithm to determine which routes it should use by taking in the cost (reference bandwidth / interface bandwidth) and other factors.

OSPF can be configured on Layer 3 (L3) devices in two different ways: via router configuration mode and via interface configuration mode.
R2 will be configured via router configuration and R1 will be configured via interface configuration mode.

Configuring OSPF on  R2:
```text
R2(config)#int g0/0/0
R2(config-if)#ip add 10.0.0.2 255.255.255.252
R2(config-if)#no shutdown
R2(config-if)#router ospf 1
R2(config-router)#network 192.168.1.0 0.0.0.255 area 0
R2(config-router)#network 192.168.2.0 0.0.0.255 area 0
R2(config-router)#network 10.0.0.0 0.0.0.3 area 0
```

Step by step, we first apply the ip address of 10.0.0.2/30 on the GigabitEthernet0/0/0 interface and turn the interface on.
We then move into router config mode for the OSPF process with the process id of 1.
Then, we advertise all networks that this router is connected to using wildcard bits (opposite of subnet mask) and the backbone area of 0.


Configuring OSPF on R1:
```text
R1(config)#int g0/0/0
R1(config-if)#ip add 10.0.0.1 255.255.255.252
R1(config-if)#no shutdown
R1(config-if)#ip ospf 1 area 0
```

We apply the same first steps for R1 except we make its address 10.0.0.1/30. 
We then advertise the interface GigabitEthernet0/0/0 instead of advertising the network route as we did in R2.

## DHCP

Dynamic Host Configuration Protocol (DHCP) would allow for clients to lease ip addresses from the DHCP server instead of us having to manually configure each one on each client.
We will configure R1 as the DHCP server and R2 will be the DHCP relay agent that would point clients who are seeking IP addresses to that DHCP server (R1).

R1 will have two different DHCP pools to account for the two different vlans that are connected to R2. 

**NOTE: In many company scenarios you most likely will use an actual DHCP server instead of making a router a DHCP server but for this demonstration I wanted to show how to configure a router as a DHCP server.**


Configuring R1 as a DHCP server:
```text
R1(config)#ip dhcp pool POOL1
R1(dhcp-config)#network 192.168.1.0 255.255.255.0
R1(dhcp-config)#default-router 192.168.1.254
R1(dhcp-config)#ip dhcp pool POOL2
R1(dhcp-config)#network 192.168.2.0 255.255.255.0
R1(dhcp-config)#default-router 192.168.2.254
```

We name both pools respective of which vlan they will serve (POOL1 for vlan 10 and POOL2 for vlan 20).
We set from what ip addresses the clients will receive and then point them to their default gateway for all their routing needs.


Configuring R2 as a DHCP relay agent:
```text
R2(config)#int g0/0/1.1
R2(config-subif)#ip helper-address 10.0.0.1
R2(config)#int g0/0/1.2
R2(config-subif)#ip helper-address 10.0.0.1
```

You just have to go into sub-interface configuration mode not interface configuration mode for the networks you would like to receive ip addresses then point to the actual DHCP server.
